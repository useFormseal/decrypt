# Output formats

`fsd decrypt` always writes the canonical JSONL ledger. Pass `--format` for additional exports. Every run **overwrites** all output files — it does not append.

## JSONL (canonical)

Written on every decrypt, regardless of `--format`.

```json
{"version": "fse.v1.0", "origin": "contact-form", "id": "uuid", "submitted_at": "2024-01-15T10:30:00Z", "data": {"name": "John"}}
```

One JSON object per line. Streaming-friendly, append-friendly as a ledger.

## JSON (`--format json`)

Pretty-printed JSON array — readable and debuggable:

```json
[
  {
    "version": "fse.v1.0",
    "origin": "contact-form",
    "id": "uuid",
    "submitted_at": "2024-01-15T10:30:00Z",
    "data": {
      "name": "John",
      "email": "john@example.com"
    }
  }
]
```

## CSV (`--format csv`)

Spreadsheet-compatible. Fields sorted alphabetically, nested values JSON-stringified.

```csv
id,origin,submitted_at,name,email
uuid1,contact-form,2024-01-15T10:30:00Z,John,john@example.com
```

Values starting with `=`, `+`, `-`, `@`, or tab are prefixed with `'` to prevent formula injection (CSV injection protection).

## Markdown (`--format md`)

Table view — quick review in any markdown viewer:

```
| id | origin | submitted_at | name | email |
|---|---|---|---|---|
| uuid1 | contact-form | 2024-01-15T10:30:00Z | John | john@example.com |
```

## Behavior notes

- **Overwrite, not append** — every `fsd decrypt` run recreates all output files from scratch
- **Canonical JSONL always written** regardless of `--format` flag
- **Extra format is a projection** of the canonical JSONL data — no additional decryption
- **Empty source** produces empty output files (warns: "Source file contains no records.")
- **Partial failures** — individual ciphertext failures are reported but don't halt processing
